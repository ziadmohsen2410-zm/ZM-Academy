# تقرير التنفيذ - ZM Academy

آخر مراجعة: 28 نوفمبر 2026

## الوظائف الموجودة في المستودع
- واجهة عامة وصفحات تسجيل الدخول وإنشاء حساب الطالب.
- لوحة الطالب: المواد والمحتوى، متابعة التقدم، المفضلة، عارض PDF، الصورة الشخصية، الإشعارات، الاختبارات، المساعد التعليمي، وتفضيلات الواجهة.
- لوحة الإدارة: الطلاب، المواد والمحتوى، الطلبات، الأجهزة، أولياء الأمور، الاختبارات والأسئلة، الإعلانات، الإشعارات، محرر الصفحة الرئيسية، Page Builder، التصميم، الأدوار والصلاحيات، الوسائط، النسخ الاحتياطي، وسجلات التدقيق.
- بوابة ولي الأمر: التسجيل والدخول وربط الأبناء وعرض ملخص التقدم والطلبات والاختبارات.
- حماية مسارات الإدارة بحسب الدور، وتحديد معدل محاولات تسجيل الدخول وطلبات الذكاء الاصطناعي.
- تخزين ملفات الأكاديمية في مستودع GitHub خاص، مع حد رفع للمحتوى يصل إلى 25 MB وحد منفصل لصورة الطالب 5 MB.
- محرر الصفحات يدعم ترتيب الكتل بالسحب والإفلات، وإخفاء العناصر حسب الجهاز، ومعاينة متجاوبة.
- رابط Facebook الرسمي مضبوط كخيار افتراضي للتواصل، مع السماح بتغييره من إعدادات الهوية. لم يتم وضع رابط YouTube غير متاح.

## تحسينات الكود الأخيرة
- اجتازت تغييرات رفع الملفات حتى 25 MB فحوصات GitHub Actions قبل دمجها.
- استُبدل استعلام كتالوج SQLite الداخلي في مسار حذف المحتوى بـ `PRAGMA table_list` الموثق في Cloudflare D1، مع تسجيل مرحلة الفشل بدقة.
- أضيفت بوابة تحقق قبل نشر Worker وفحص صحة بعد النشر يتأكد من اتصال D1.
- اجتازت تغييرات إصلاح حذف المحتوى، ورابط Facebook، وسير عمل النشر فحوصات الجودة في GitHub Actions.

## ما لا يمكن اعتباره مكتملًا دون إعداد/اختبار خارجي
1. **النشر الحي:** يجب التأكد من نجاح آخر تشغيل لسير عمل نشر Worker، ثم فحص `/api/health` وأن النتيجة `success=true` و`database=connected`.
2. **قاعدة الإنتاج:** يجب مراجعة مخطط D1 الفعلي وتطبيق أي migrations مطلوبة بعد نسخة احتياطية. لا تُنفّذ تغييرات مدمرة على قاعدة الإنتاج من دون اختبار.
3. **التخزين:** يجب التأكد من وجود `GITHUB_STORAGE_TOKEN` وصلاحية الكتابة والقراءة والحذف في مستودع التخزين.
4. **حساب الإدارة:** يتطلب الإعداد الأول وجود `ADMIN_SETUP_KEY` واستخدامه مرة واحدة لإنشاء أول حساب إداري بكلمة مرور قوية.
5. **الذكاء الاصطناعي:** واجهات المساعد والـAI Builder ومساعد الإدارة موجودة، لكن الاستجابات الحقيقية تتطلب ضبط `AI_API_KEY` (ويمكن ضبط `AI_API_URL` و`AI_MODEL` اختياريًا). لا يمكن تفعيل الخدمة من دون مفتاح مزود صالح.
6. **اختبارات التشغيل:** اجتاز مسار الحذف الدائم اختبارًا حيًا على Preview D1: تم إنشاء حساب إدارة مؤقت، وتسجيل الدخول، وحذف مادة مرتبطة بطلب شراء وسجل تقدم ومفضلة وأرشيف وجدول تابع إضافي، ثم التأكد من اختفاء جميع السجلات التابعة. ما زال يلزم اختبار بقية رحلات الطالب وولي الأمر والأجهزة والرفع الفعلي للملفات الكبيرة والعرض.
7. **الدفع الإلكتروني:** لا توجد بوابة دفع مرتبطة بمزود حقيقي في المستودع الحالي؛ لا تُعرض المدفوعات الإلكترونية على أنها مفعّلة.

## قرار الإطلاق
حالة المستودع: فحوصات الجودة الآلية ناجحة، واختبار الحذف الدائم المتكامل على Preview D1 ناجح بعد استبعاد جداول Cloudflare الداخلية ذات البادئة `_cf_` من فحص علاقات الجداول.
حالة الإطلاق العام: **غير معتمدة بعد** إلى أن تكتمل اختبارات Preview الحية، وتأكيد نشر Worker وD1، وإعداد الأسرار المطلوبة. نجاح الفحوصات الثابتة لا يثبت وحده أن كل رحلة مستخدم تعمل على الإنتاج.
