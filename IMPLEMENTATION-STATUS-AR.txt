ZM Academy — تقرير حالة التنفيذ
تاريخ الحزمة: 26 نوفمبر 2026
مرجع الأساس: ZM-Academy-Phase1-Control-Center.zip

أولًا: ما تم تنفيذه في هذه الحزمة
1. الإبقاء على ملفات الواجهة وWorker ومخطط D1 الحالي دون حذف جداول المشروع القديمة أو إعادة إنشائها.
2. تنظيم لوحة الإدارة الحالية وإضافة أقسام للإحصائيات والصفحات وأولياء الأمور والإعلانات والإشعارات والتقارير وسجل التدقيق والأدوار والذكاء الاصطناعي والاختبارات.
3. Visual Page Builder بعناصر محددة وآمنة (عنوان، نص، زر، بطاقة، صورة، تنبيه، قسم، مسافة، رابط فيديو)، مع تحرير المحتوى وبعض الأنماط، إظهار/إخفاء، حذف، ترتيب بالسحب والإفلات وأزرار تحريك، معاينة أجهزة، حفظ المسودة، النشر، سجل إصدارات واستعادة كمسودة.
4. منع HTML وJavaScript الحرين داخل محرر الصفحات؛ يتم تخزين JSON وفق مخطط allowlist والتحقق منه على الخادم.
5. إضافة Theme/Design controls أساسية سابقة للمشروع، وربط إعدادات تفضيلات الطالب الشخصية (ألوان وثيم وقالب وحجم خط وتخطيط بطاقات وترتيب أقسام وحركة) بحساب الطالب في D1 مع قيود تحقق.
6. بوابة ولي أمر بحساب منفصل وكلمات مرور PBKDF2 وجلسات مستقلة، وطلبات ربط تتحقق من رقم ولي الأمر المسجل في سجل الطالب وتحتاج اعتماد الإدارة، مع عرض الأبناء والمواد والطلبات ومؤشر التقدم ونتائج الاختبارات المعتمدة والإشعارات والإعلانات.
7. نظام اختبارات يدعم اختيارًا متعددًا وصح/خطأ ومقاليًا، الزمن وعدد المحاولات والجدولة والصف والمادة والنشر والأرشفة والتصحيح الآلي ومراجعة المقالي وملاحظات المدرس ونتائج الطالب. مفاتيح الإجابة لا تُرسل للطالب قبل التصحيح.
8. مركز إعلانات بمواضع وجمهور وفترات زمنية وأولوية وحالة، مع عداد مشاهدات ونقرات.
9. إشعارات مجدولة موجهة لكل الطلاب أو صف أو طالب أو أولياء الأمور أو ولي أمر محدد، مع حالة القراءة.
10. مساعد طالب ومساعد إدارة وAI Builder اقتراحي وAI Content Studio لإنشاء مسودات تعليمية؛ كل اتصالات المزود تتم من Worker، ويحتاج تشغيلها إلى أسرار، ولا ينفذ AI أوامر إدارة تلقائيًا.
11. صلاحيات أدوار على الخادم للمسارات الإدارية الجديدة والقديمة غير المصنفة، وسجل تدقيق لبعض العمليات الإدارية الجديدة.
12. مكتبة وسائط أساسية: رفع PDF وصور JPG/PNG/WEBP إلى GitHub Storage من Worker، التحقق من ترويسة الملف الفعلية وحجمه، حفظ الاسم والتصنيف والوصف البديل في D1، تحكم بنشر الصور العامة ومعاينتها، وإيقاف حذف الملفات المرتبطة بمواد أو صفحات منشورة. روابط الوسائط العامة تمر عبر Worker ولا تكشف Token.
13. تصحيح قواعد الأجهزة: الطلب الجديد لا يوقف الجهاز المعتمد السابق، واعتماد جهاز جديد لا يلغي الأجهزة والجلسات المعتمدة الأخرى. إلغاء الجهاز يظل عبر مساره المستقل.
14. الحفاظ على تاريخ الطلبات: إخفاء/إزالة الطلب من واجهة الطالب لم يعد يحذف السجل الأصلي؛ يسجل إخفاءً لكل طالب.
15. Migration إضافية idempotent لا تستخدم DROP أو DELETE ولا تعيد إنشاء جداول الطلاب أو المواد أو الطلبات.
16. إضافة اختبارات آلية للتحقق من مخططات البيانات وفحص صياغة JavaScript inline في صفحات HTML واختبار تطبيق migration مرتين مع الحفاظ على سجلات سابقة.

ثانيًا: ما هو جزئي أو محدود
- محرر الصفحات ليس بديلًا كاملًا عن محرر تصميم حر مثل Webflow: لا يسمح بأكواد مخصصة، ويغطي حاليًا أنواع العناصر والخصائص المحددة في الواجهة وWorker. المعاينة داخل اللوحة وليست بيئة مطابقة 1:1 لكل المتصفحات.
- Theme Studio يغطي خيارات الألوان والقوالب الموجودة وأجزاء من عناصر التصميم؛ لا يوفر بعد كل الخصائص التفصيلية لكل مكوّن في كل نقطة استجابة.
- بوابة ولي الأمر تعتمد على مطابقة رقم الهاتف المسجل وموافقة الإدارة؛ لا يوجد OTP SMS/WhatsApp أو استعادة كلمة مرور ولي الأمر حتى الآن.
- تقارير Analytics الحالية تعرض مؤشرات أساسية من الجداول الموجودة؛ لا تقدم بعد كل التحليلات التفصيلية أو مخططات الاتجاهات أو تصدير PDF موثوق.
- سجل التدقيق يسجل العمليات الجديدة المحددة، وليس كل حدث تاريخي أو كل مسارات Worker القديمة.
- AI Student Assistant يتلقى سياق مواد الطالب الأساسية، ولا ينفذ بعد فهرسة كاملة للدروس وملفات PDF أو فهم رفع الصور والملفات.
- AI Admin Assistant يقدم اقتراحات نصية؛ لا يقرأ قاعدة البيانات لتوليد تقارير مخصصة ولا ينفذ إجراءات CMS. AI Builder يطلب مقترحات آمنة لكن يلزم على المسؤول نقل/تعديل العناصر داخل المحرر ومراجعتها.
- AI Content Studio يحفظ المسودة ويعتمدها داخليًا؛ الاعتماد لا ينشرها تلقائيًا في مكتبة الدروس أو بنوك الأسئلة.
- مكتبة الوسائط الجديدة تغطي الرفع والتصنيف والوصف البديل والنشر العام والحذف الآمن الأساسي؛ لا تزال تفتقر إلى قص/تحويل الصور، مجلدات فعلية داخل مستودع التخزين، بحث متقدم، معاينة PDF وإدارة أذونات لكل ملف.
- الإشعارات تنشئ مستلمين حتى حد 1500 مستلم في العملية؛ التوزيع واسع النطاق يحتاج Queue/Batching.
- إدارة الأدوار متاحة، لكن التعيينات القديمة غير الموجودة في جدول الأدوار تعامل كـSuper Admin للحفاظ على صلاحيات المسؤولين الحاليين؛ يجب تعيين أدوار مقيدة صراحة بعد مراجعة الحسابات.

ثالثًا: ما لم يتم تنفيذه بعد
- خدمة نسخ احتياطي تلقائي مجدول واستعادة من داخل لوحة الإدارة مع عزل تجريبي.
- تشفير خاص لبيانات شخصية إضافية عند التخزين، وإدارة موافقات خصوصية/احتفاظ متقدمة.
- مدفوعات إلكترونية فعلية أو تكامل بوابة دفع.
- رسائل SMS/WhatsApp/Email فعلية.
- محرر وسائط شامل مع القص والتحويل والفهرسة المتقدمة والمجلدات الحقيقية.
- تقارير PDF شاملة واختبارات واجهة end-to-end على أجهزة حقيقية.
- اختبارات تكامل مباشرة مع Cloudflare D1/Workers وGitHub Storage ومزود AI.
- مزامنة التغييرات إلى مستودع GitHub أو نشر GitHub Pages/Cloudflare من هذه البيئة.

رابعًا: قيود التحقق
- لم يتم الاتصال بحساب Cloudflare، ولم تُطبق migration على قاعدة D1 الحية.
- لم يتم النشر أو اختبار API على الخدمة الحية.
- تعذر استنساخ GitHub من بيئة التنفيذ بسبب DNS؛ النسخة العاملة مستندة إلى ZIP المرفق مع مطابقة بنية المستودع العام بقدر ما أمكن.
- نتائج الاختبارات النهائية في docs/TEST-REPORT-AR.txt.
